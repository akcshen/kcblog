# Vite Proxy、Node 代理环境变量与 Clash 分流不生效问题排查

## 一、问题背景

在 Vue + Vite 项目开发过程中，经常会遇到这样的场景：

* 前端通过 Vite `proxy` 代理访问后端接口。
* 本地电脑开启 Clash 代理。
* 已经在 Clash 中配置了规则：

```yaml
IP-CIDR,192.200.125.79/32,DIRECT
```

希望访问内网后端：

```
http://192.200.125.79:9097
```

时不要经过代理。

但是实际表现：

* 浏览器访问接口异常。
* Clash 规则看起来没有生效。
* 给 Vite proxy 添加 `agent` 后反而正常。

问题的根源在于：

**浏览器代理、Clash 规则、Node/Vite 代理并不是同一个代理链路。**

---

# 二、请求链路分析

正常情况下，Vue 开发环境请求流程：

```
浏览器
  |
  | localhost:3333
  ↓
Vite Dev Server
  |
  | Node HTTP Request
  ↓
192.200.125.79:9097
```

这里有两个不同角色：

1. 浏览器
2. Node（Vite proxy）

很多人误以为：

> 开启 Clash 后，所有程序都会经过 Clash。

实际上不是。

---

# 三、为什么 Clash 规则不生效？

## 1. Clash 规则只控制进入 Clash 的流量

例如：

```yaml
rules:
  - IP-CIDR,192.200.125.79/32,DIRECT
```

作用是：

```
应用程序
   |
   ↓
Clash
   |
   ↓
匹配规则
   |
   ↓
DIRECT
```

前提：

> 请求必须先进入 Clash。

---

## 2. Node 请求可能读取系统代理变量

Node 运行环境可能存在：

```bash
HTTP_PROXY
HTTPS_PROXY
ALL_PROXY
```

例如：

```bash
ALL_PROXY=socks5h://127.0.0.1:10808
```

此时：

```
Vite(Node)
    |
    ↓
读取代理环境变量
    |
    ↓
SOCKS代理
    |
    ↓
目标服务器
```

这个过程可能不会经过 Clash Rule。

因此：

Clash 配置：

```
192.200.125.79 DIRECT
```

不会生效。

---

# 四、如何确认问题

## 1. 查看代理环境变量

执行：

```bash
env | grep -i proxy
```

可能看到：

```bash
ALL_PROXY=socks5h://127.0.0.1:10808
```

说明当前终端存在代理。

---

## 2. curl 测试

普通：

```bash
curl -v http://localhost:3333
```

如果看到：

```
Uses proxy env variable all_proxy
```

说明 curl 正在使用代理。

关闭代理测试：

```bash
curl --noproxy "*" -v http://localhost:3333
```

---

# 五、解决方案

## 方案一：使用 NO_PROXY（推荐）

告诉 Node：

这些地址不要走代理。

配置：

```bash
export NO_PROXY="localhost,127.0.0.1,::1,192.200.125.79"
export no_proxy="$NO_PROXY"
```

效果：

请求：

```
192.200.125.79
```

直接访问：

```
Node
 |
 ↓
192.200.125.79
```

不会经过代理。

---

## 六、永久配置

macOS 默认 Shell：

```bash
zsh
```

编辑：

```bash
vim ~/.zshrc
```

增加：

```bash
export NO_PROXY="localhost,127.0.0.1,::1,192.200.125.79"
export no_proxy="$NO_PROXY"
```

加载：

```bash
source ~/.zshrc
```

之后新开的终端都会生效。

---

# 七、VS Code 注意事项

如果 Vue 项目是在 VS Code 中启动：

修改 `.zshrc` 后：

不要直接继续运行旧窗口。

需要：

1. 完全退出 VS Code
2. 重新打开 VS Code
3. 新建 Terminal
4. 再执行：

```bash
npm run dev
```

原因：

VS Code 启动时会继承当时的环境变量。

---

# 八、为什么添加 agent 可以解决？

例如：

```js
proxy: {
  '/obd': {
    target: 'http://192.200.125.79:9097',
    agent
  }
}
```

本质是：

手动指定 Node 请求走某个代理。

它绕过了系统环境的不确定性。

但是缺点：

* 每个项目都需要配置。
* 不方便维护。

如果多个 Vue 项目开发，更推荐：

```
统一配置 NO_PROXY
```

---

# 九、最终推荐方案

开发环境：

## Clash

负责：

* 浏览器代理
* 系统代理
* TUN 流量

配置：

```yaml
rules:
  - IP-CIDR,192.200.125.79/32,DIRECT
```

---

## Node/Vite

负责：

* 本地开发代理

配置：

```bash
NO_PROXY=localhost,127.0.0.1,::1,192.200.125.79
```

---

最终链路：

```
Chrome
 |
 | Clash规则控制
 ↓
Clash


Vite(Node)
 |
 | NO_PROXY控制
 ↓
192.200.125.79
```

两套代理体系分别管理，避免互相影响。

---

# 十、总结

遇到：

> Clash 已配置 DIRECT，但是 Vite proxy 仍然走代理

不要只检查 Clash。

应该同时检查：

1. 是否存在 `HTTP_PROXY / HTTPS_PROXY / ALL_PROXY`
2. Node 是否读取代理环境变量
3. 是否配置 `NO_PROXY`
4. Vite proxy 是否被绕过
5. 浏览器请求是否真的经过 Vite

核心认知：

**Clash 管的是进入 Clash 的流量；Node 管的是 Node 自己的代理环境。两者不是一回事。**
